사용자가 `/mobile $ARGUMENTS` 를 실행했다. 대상 탭에 **모바일(<=768px) 전용 뷰**를 신설하는 진입점이다.
절차 규범은 `mobile-blueprint` 스킬, 구조 정본은 `.claude/memory/service/mobile-architecture.md`,
구현은 `mobile-view-agent` 가 맡는다. 레퍼런스 구현 = 샘플반납.

## 인자가 **있을 때** (`/mobile <탭>`) — 신설 절차 실행

`mobile-blueprint` 스킬을 호출해 그 절차를 따른다:

1. **탐색(읽기 전용)** — 대상 탭의 메모리 3종 · 데스크톱 뷰 · 위젯 · API · 정본 팔레트 ·
   **공유 로직이 위젯에 갇혀 있는지** · 제외 후보(iframe·엑셀·대량편집).
2. **계획 제시** — 서브탭별 `이식/축약/제외` 표, 로직 추출 목록, 남길 편집, 팔레트 매핑, 변경 파일, 검증 계획.
   결정 포인트(이식 범위·편집 허용·로직 추출)는 **AskUserQuestion**. **승인 전 파일 생성·수정 금지.**
3. **구현** — 승인된 plan 전문을 주고 `mobile-view-agent` 에 **Agent 도구로 위임**.
   서브탭이 많으면 묶음별 병렬 위임하되 **CSS 델타·라우트 래핑은 1곳에서만**(충돌 방지).
4. **검증** — `mobile-architecture.md` §6. 특히 **데스크톱 == 모바일 수치 일치**(다르면 로직 이중화 사고)와
   **데스크톱 무손상**. 돌린 명령과 결과를 명시하고, 못 돌린 것은 못 돌렸다고 쓴다.
5. **마무리** — `mobile-architecture.md` §5 현황 표에 행 추가. 커밋·`/server-test` 는 **명시 승인 후에만**.

이미 모바일 뷰가 있는 탭이면 신설이 아니라 **수정**임을 먼저 알리고 범위를 확인한다.

예) `/mobile vmd` → VMD 5서브탭 탐색 후 이식 범위 계획 제시.
`/mobile 지급율` → 지급율 3서브탭 중 오버뷰 우선 이식 + 엑셀 제외 계획 제시.
