사용자가 `/소매리오더 $ARGUMENTS` 를 실행했다. 소매 리오더 탭(실행·리포트·데이터) 작업을 전담 에이전트로 위임하는 진입점이다.
라우팅·회귀검증 규범은 `retail-reorder` 스킬, 업무규칙은 `.claude/memory/domain/retail-reorder.md`, 구조는 `.claude/memory/service/retail-reorder-architecture.md` 를 따른다.

## 인자가 **없을 때** (`/소매리오더` 단독) — 에이전트 목록 표시

아래 표를 **그대로 출력**하고, "번호·영역명·에이전트명 중 무엇으로든 지정하면 해당 에이전트로 바로 위임합니다. 여러 영역이면 함께 적어주세요."라고 안내한 뒤 사용자의 선택을 기다린다. (임의로 에이전트를 먼저 호출하지 않는다.)

| # | 영역 | 에이전트 | 담당 |
|---|---|---|---|
| 0 | 리포트·전체핵심 | `retail-reorder-report-agent` | 매장별 요약(행거·지급율·미송)·KPI·주문표 모달(필터/정렬/미송)·빌드 이력 조회 |
| 1 | 실행·생성 UI | `retail-reorder-run-agent` | 주문 파라미터·안전재고 설정·PKL 상태·생성 트리거·진행 폴링 |
| 2 | 데이터 파이프라인 | `retail-reorder-data-agent` | order_router/order_service·order_build_* 조회 스키마·/store-metrics 병렬집계 |

> 공통 셸(`OrderView.js`)·`order_service` 응답 키·`order_build_*` 스키마·`/store-metrics` 재사용 등 **여러 영역에 걸친 변경**은 `retail-reorder` 스킬 §2(공유 자산)대로 영향 에이전트를 함께 위임한다.
> 경계: 주문장 *생성·배포 운영* → `order-agent`, 리포트 내 베스트3종 → `best-*`, 기획/주문추천 → `md-agent`.

## 인자가 **있을 때** (`/소매리오더 <요청>`) — 직접 라우팅

1. `$ARGUMENTS` 에서 대상 영역(들)을 위 표로 식별한다. 모호하면 AskUserQuestion 으로 1회 확인.
2. 식별된 에이전트를 **Agent 도구로 즉시 위임**한다(요청 원문 + 관련 파일 컨텍스트 전달). 여러 영역이면 **단일 메시지로 병렬 위임**.
3. 에이전트가 공유 자산 변경을 보고하면 영향 영역을 추가 위임하거나 메인이 조정한다.
4. 작업 후 `retail-reorder` 스킬 §3 회귀 게이트(import 스모크·탭 렌더·콘솔 0·빌드리스·타 탭 무손상)로 검증한다.

예) `/소매리오더 매장별 요약에 컬럼 추가` → `retail-reorder-report-agent`(+ 스키마 변경 시 `retail-reorder-data-agent` 병렬). `/소매리오더 store-metrics 집계 수정` → `retail-reorder-data-agent`. `/소매리오더 안전재고 UI 변경` → `retail-reorder-run-agent`. `/소매리오더 주문장 생성 산식 바꿔` → 경계상 **order-agent** 로 라우팅.
