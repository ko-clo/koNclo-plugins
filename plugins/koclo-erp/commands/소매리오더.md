사용자가 `/소매리오더 $ARGUMENTS` 를 실행했다. 소매 리오더 탭(실행·리포트·마스터주문·상품마스터·주문장 상세·데이터) 작업을 전담 에이전트로 위임하는 진입점이다.
라우팅·회귀검증 규범은 `retail-reorder` 스킬, 업무규칙은 `.claude/memory/domain/retail-reorder.md`, 구조는 `.claude/memory/service/retail-reorder-architecture.md` 를 따른다.

## 인자가 없을 때 (`/소매리오더` 단독) — 에이전트 목록 표시

아래 표를 그대로 출력하고, "번호·영역명·에이전트명 중 무엇으로든 지정하면 해당 에이전트로 바로 위임합니다. 여러 영역이면 함께 적어주세요."라고 안내한 뒤 사용자의 선택을 기다린다. 임의로 에이전트를 먼저 호출하지 않는다.

| # | 영역 | 에이전트 | 담당 |
|---|---|---|---|
| 0 | 리포트·전체핵심·주문장 상세 | `retail-reorder-report-agent` | KPI·상단 재계산바·매장별 요약(행거/지급율/샘플/미송)·주요 상품·주문표 모달·빌드 이력·`OrderSheetView` |
| 1 | 마스터주문·상품 마스터 | `retail-reorder-report-agent` + 데이터 계약 변경 시 `retail-reorder-data-agent` | 마스터주문 후보/예산/선택반영, 상품 마스터 워크북/시트/매장/검색/페이징 |
| 2 | 실행·생성 UI | `retail-reorder-run-agent` | 주문 파라미터·안전재고·데이터 상태·생성 트리거·진행 폴링·멈추기 |
| 3 | 데이터 파이프라인 | `retail-reorder-data-agent` | order_router/order_service 전체, order_build_* 스키마, store-metrics, data-status, master-order/master-add 응답 계약 |

> 공통 셸(`OrderView.js`)·`OrderSheetView.js`/`orderDetailShared.js`·`order_service` 응답 키·`order_build_*` 스키마·`/store-metrics`·마스터주문 반영은 여러 영역에 걸친 변경이다.
> 경계: 주문장 생성 산식·xls 검수·배포 운영 → `order-agent`, 베스트상품 정본 계산/화면 → `best-*`, 기획/주문추천 → `md-agent`.

## 인자가 있을 때 (`/소매리오더 <요청>`) — 직접 라우팅

1. `$ARGUMENTS` 에서 대상 영역(들)을 위 표로 식별한다. 모호하면 AskUserQuestion 으로 1회 확인한다.
2. 식별된 에이전트를 Agent 도구로 즉시 위임한다(요청 원문 + 관련 파일 컨텍스트 전달). 여러 영역이면 단일 메시지로 병렬 위임한다.
3. 에이전트가 공유 자산 변경을 보고하면 영향 영역을 추가 위임하거나 메인이 조정한다.
4. 작업 후 `retail-reorder` 스킬 §3 회귀 게이트로 검증한다.

예)
- `/소매리오더 매장별 요약 샘플건 이상해` → `retail-reorder-report-agent` + store-metrics 계약이면 `retail-reorder-data-agent`.
- `/소매리오더 마스터주문 목표 지급율 계산 고쳐` → `retail-reorder-report-agent` + `retail-reorder-data-agent`.
- `/소매리오더 상품 마스터 매장 필터 추가` → `retail-reorder-report-agent`(master-sheet API 변경이면 data/backend 소관 확인).
- `/소매리오더 데이터 상태 색상 고쳐` → `retail-reorder-run-agent`.
- `/소매리오더 주문장 생성 산식 바꿔` → 경계상 **order-agent** 로 라우팅.
