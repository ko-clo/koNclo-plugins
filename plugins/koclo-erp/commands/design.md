사용자가 `/design $ARGUMENTS` 를 실행했다.
절차 정본은 `dev-workflow` 스킬, 강제는 PreToolUse 훅 `.claude/hooks/design-gate.sh`,
배경·운용은 `.claude/memory/meta/dev-workflow.md` 를 따른다.

## 0. 인자 해석 — 게이트 조작인가, 작업 요청인가

`$ARGUMENTS` 의 **첫 토큰**이 `on` / `off` / `status` 이고 **뒤에 숫자 외의 내용이 없으면** 게이트 조작(§1)이다.
그 외( `/design 재고 탭에 필터 추가` 등)는 전부 **작업 요청**(§2)으로 처리한다.
인자가 아예 없으면 §3 안내를 출력한다.

## 1. 게이트 조작 (`.claude/.design-unlock` — 만료 epoch 한 줄)

게이트가 열린 동안에만 `backend/**`·`frontend/**` 편집이 훅을 통과한다.
(`/nas on`·`/danger on`·`/testfile on` 과 **같은 의미** — `on` = 한시 허용, `off` = 잠금)

- **on [분]** (분 생략 시 30):
  `EXP=$(( $(date +%s) + <분>*60 )); printf '%s\nmode=bypass\n' "$EXP" > .claude/.design-unlock`
  실행 후 `⚠️ 작업 모드 게이트 <분>분 해제 (만료 HH:MM) — 간단·긴급 작업용` 출력.
- **off**: `rm -f .claude/.design-unlock` 실행 후 `🛑 작업 모드 게이트 잠금` 출력.
- **status** 또는 인자 없음과 함께 물으면: 파일 존재·남은 시간을 계산해 출력. 없거나 만료면 `🛑 잠김`.

### 게이트를 여는 것은 사용자만 한다

Claude 는 게이트를 **임의로 열지 않는다.** 두 가지 경우에만 열린다.

1. **정상 경로** — `dev-workflow` §3 승인 게이트를 사용자가 승인했을 때. 스킬이 240분으로 연다.
2. **우회 경로** — 사용자가 직접 `/design on [분]` 을 실행했을 때.

우회는 **간단한 수정·긴급 대응**을 위한 것이다. 우회로 열었더라도 **① 모드 분류 배너 하나는 남기고**
(`dev-workflow` §1) 작업하며, 끝나면 `/design off` 로 잠근다. 게이트는 짧게 연다.

## 2. 작업 요청 처리 (`/design <요청>`)

`dev-workflow` 스킬을 그대로 따른다. **모든 스텝은 스킬 §1 의 스텝 배너**
(`---` 구분선 + `### <번호> <이름> — <결론>` + 진행 레일 + `>` 요약)를 달고 출력한다. 요약:

1. **① 모드 분류** — 기능추가 | 기능수정 | 버그해결 + 판단 근거(요청 인용). 모호하면 AskUserQuestion 1회.
2. **② 조사 위임** — `dev-investigator-agent` (읽기전용). 파일 2~3개로 끝나는 작은 건은 메인이 직접.
3. **③ 설계 위임** — 모드별 전담 에이전트:

   | 모드 | 에이전트 |
   |---|---|
   | 기능추가 | `dev-feature-design-agent` |
   | 기능수정 | `dev-change-impact-agent` |
   | 버그해결 | `dev-bug-triage-agent` |

4. **④ 승인 게이트 출력** — `dev-workflow` §3 템플릿(조사요약·구현방향·선택이유·Trade-off·영향범위·검증계획)
   + 모드별 산출물. **여기서 멈추고 사용자 승인을 기다린다.**
5. **승인 후** — 게이트 개방(§1 정상 경로) → **⑤ 구현** 위임(`dev-workflow` §5)
   → **⑥ 검증** `dev-verify-agent` → **⑦ 완료 보고** `dev-workflow` §6 → `/design off`.

위임한 에이전트의 보고를 배너 없이 그대로 붙여넣지 않는다 — 메인이 해당 스텝 배너를 씌워 전달한다.

**승인 전에는 코드 작성·파일 수정·마이그레이션·커밋·배포를 하지 않는다.**
훅이 차단하지만 규칙이 먼저다 — 훅에 막히고 나서 승인을 요청하는 것은 순서가 틀렸다.

## 3. 인자가 없을 때 (`/design` 단독)

아래를 출력하고 사용자의 요청을 기다린다(임의로 작업을 시작하지 않는다).

| 모드 | 언제 쓰나 | 설계 에이전트 |
|---|---|---|
| **기능추가** | 새 기능·화면·API·DB 구조·워크플로우 신설 | `dev-feature-design-agent` |
| **기능수정** | 기존 동작·로직·UI·응답·계산식 변경 | `dev-change-impact-agent` |
| **버그해결** | 에러·오작동·예외·데이터 불일치 제거 | `dev-bug-triage-agent` |

```
/design <작업 요청>   작업 모드 분류 → 조사·설계 → 승인 → 구현
/design status        게이트 상태
/design on [분]       게이트 한시 해제 (기본 30분, 간단·긴급용)
/design off           게이트 잠금
```

현재 게이트 상태도 함께 표시한다(§1 status).
