사용자가 `/도매리오더 $ARGUMENTS` 를 실행했다. 도매 리오더 탭(리포트·액션·데이터) 작업을 전담 에이전트로 위임하는 진입점이다.
라우팅·회귀검증 규범은 `wholesale-reorder` 스킬, 업무규칙은 `.claude/memory/domain/wholesale-reorder.md`, 구조는 `.claude/memory/service/wholesale-reorder-architecture.md` 를 따른다.

## 인자가 **없을 때** (`/도매리오더` 단독) — 에이전트 목록 표시

아래 표를 **그대로 출력**하고, "번호·영역명·에이전트명 중 무엇으로든 지정하면 해당 에이전트로 바로 위임합니다. 여러 영역이면 함께 적어주세요."라고 안내한 뒤 사용자의 선택을 기다린다. (임의로 에이전트를 먼저 호출하지 않는다.)

| # | 영역 | 에이전트 | 담당 |
|---|---|---|---|
| 0 | 리포트·카드 | `wholesale-reorder-report-agent` | 소스필터(코스/본사)·키워드섹션(리오더/후보/확장/소진/정상)·카드·KPI·기주문추적·도매외부·원천점검(coverage/self_check) |
| 1 | 액션·재계산 | `wholesale-reorder-action-agent` | 풀 재계산(워크북 인입 트리거)·매장 이동·정리(분배/이고/회수)·실행지시 엑셀·발주확정 |
| 2 | 데이터 파이프라인 | `wholesale-reorder-data-agent` | wholesale_router/service·compute_data·db_adapters·ingest·serialize·_vendor 빌더·스냅샷 스키마 |

> 공통 셸(`WholesaleView.js`)·`compute_data` payload 키·`wholesale_report_snapshots` 스키마·`_vendor` 빌더 등 **여러 영역에 걸친 변경**은 `wholesale-reorder` 스킬 §2(공유 자산)대로 영향 에이전트를 함께 위임한다.
> 경계: batch CSV *인입·cron 운영* → `batch-ingest`, 빌더 *산식 정본* → `_vendor` 재복사, 본사/매장 정본 집계 → `vmd-data`/`payrate-data`.

## 인자가 **있을 때** (`/도매리오더 <요청>`) — 직접 라우팅

1. `$ARGUMENTS` 에서 대상 영역(들)을 위 표로 식별한다. 모호하면 AskUserQuestion 으로 1회 확인.
2. 식별된 에이전트를 **Agent 도구로 즉시 위임**한다(요청 원문 + 관련 파일 컨텍스트 전달). 여러 영역이면 **단일 메시지로 병렬 위임**.
3. 에이전트가 공유 자산 변경을 보고하면 영향 영역을 추가 위임하거나 메인이 조정한다.
4. 작업 후 `wholesale-reorder` 스킬 §3 회귀 게이트(import 스모크·탭 렌더·콘솔 0·빌드리스·타 탭 무손상)로 검증한다.

예) `/도매리오더 카드에 지표 추가` → `wholesale-reorder-report-agent`(+ payload 키 변경 시 `wholesale-reorder-data-agent` 병렬). `/도매리오더 분배 산식 표시 바꿔` → `wholesale-reorder-action-agent`. `/도매리오더 db 어댑터 수정` → `wholesale-reorder-data-agent`. `/도매리오더 batch CSV 인입 고쳐` → 경계상 **batch-ingest** 로 라우팅.
