# /learn — 세션 교훈을 피드백 파일에 누적

`meta/agent_kernel.md §1` 은 *"지적을 받으면 즉시 F번호를 추가하라"* 고 지시해왔다.
그러나 **지시문만으로는 축적되지 않았다** — feedback 파일 12개 중 7개가 0건이다(`docs/harness-audit.md` A4).
이 커맨드가 그 지시를 **실행 가능한 절차**로 만든다.

인자: `$ARGUMENTS` (토픽명. 비어 있으면 세션 내용으로 판정)

---

## 1. 지적 신호 추출

이번 세션에서 사용자가 **교정·반박·불만**을 표한 지점을 찾는다. 신호 예:

> "이거 이상해" · "이렇게 해야지" · "왜 그래" · "다시" · "안 맞는다" · "아니" · "그게 아니라"
> · "확인해봐" · 같은 요청 반복 · 내 결과물을 되돌리라는 지시

**신호가 하나도 없으면 아무것도 쓰지 말고 그렇게 보고하라.** 없는 교훈을 지어내지 않는다.

## 2. 토픽 판정

`$ARGUMENTS` 가 있으면 그 토픽. 없으면 지적 내용으로 판정한다.
대상 파일은 `agent_kernel.md §1` 의 매핑표가 정본이다:

| 계열 | 피드백 파일 |
|---|---|
| order / auto-payment / md / returns | `.claude/memory/domain/<계열>-feedback.md` |
| backend | `.claude/memory/service/backend-agent-feedback.md` |
| vmd / payrate / best-products / retail-reorder / score-ranking / post-process / color-trend / wholesale-reorder | `.claude/memory/domain/<탭>-feedback.md` |

판정이 애매하면 **AskUserQuestion 으로 물어라.** 엉뚱한 파일에 적재하는 것이 안 적는 것보다 나쁘다.

## 3. 다음 F번호 계산 (반드시 실측)

기억이나 추정으로 번호를 매기지 마라. 파일에서 직접 읽는다:

```bash
F=.claude/memory/domain/<토픽>-feedback.md
mx=$(grep -oE '^#{1,4} *F[0-9]+' "$F" | grep -oE '[0-9]+' | sort -n | tail -1)
echo "다음 번호: F$(( ${mx:-0} + 1 ))"
```

F 블록이 하나도 없으면 **F1** 부터 시작한다.

## 4. 블록 작성 — `agent_kernel.md §1` 형식 고정

기존 59개 블록이 전부 `##` 레벨이다. **레벨을 바꾸지 마라**(§3 의 번호 계산이 깨진다).

```markdown
## F{번호} — {한 줄 요약}
**상황**: {언제, 무슨 작업 중, 무엇이 잘못됐나. 날짜 포함}

**지시**: {사용자가 실제로 한 말. 각색하지 말고 그대로}

**교훈**: {일반화된 규칙. 다음에 같은 상황에서 무엇을 다르게 할 것인가}

**적용방법**: {구체적으로 어떤 파일·함수·절차를 어떻게 바꾸는가}
```

- **지시는 사용자의 말을 그대로** 옮긴다. 내 해석으로 바꾸면 나중에 근거가 사라진다
- 교훈은 이 사건에만 통하는 게 아니라 **재발 방지가 되도록** 일반화한다

## 5. append — 절대 규칙

- **파일 맨 아래에 추가만 한다.** 기존 F 블록은 **한 글자도 수정·삭제하지 않는다** (§1-5 역사 보존)
- 파일이 없으면 frontmatter 를 갖춰 새로 만든다:

```markdown
---
name: {토픽} 에이전트 피드백 누적
description: {토픽} 작업 중 사용자 지적·교정의 영구 누적(F1~). 동일 실수 반복 방지. 작업 시작 전 필독.
type: feedback
---

# {토픽} 피드백 누적 (영구 학습)
```

> `description` 은 `memory-recall.py` 훅의 매칭 키다. 그 토픽에서 실제 쓰는 용어를 넣어라.

## 6. 5건 누적 시 규칙 흡수 제안

해당 파일의 F가 **5건 이상**이면, 반복 패턴을 통합 규칙 파일(`domain/<토픽>.md`)로
승격할지 **제안만** 한다. 흡수는 사용자 승인 후에 한다 — F 원본은 그대로 둔다.

## 7. 보고

- 어느 파일에 **F 몇 번**을 추가했는지
- 기존 블록 무손상 확인: `git diff --stat` 로 **추가 줄만** 있는지 보여라
- 추출했으나 적지 않은 지적이 있으면 그 이유

## 금지

- 지적이 없는데 F를 만들어내는 것
- 기존 F 수정·삭제·번호 재정렬
- 사용자 말을 요약·미화해서 `**지시**` 에 적는 것
- 토픽이 애매한데 추측으로 적재하는 것
