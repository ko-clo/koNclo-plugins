---
description: develop → main 승격 PR 생성 (작업자 정책의 배포 절차 정본)
---

사용자가 "배포해"라고 지시했다. 아래 절차를 순서대로 수행한다.

이 지시 자체가 **PR 생성 승인**이다. 올릴지 말지를 다시 묻지 않는다. 다만 무엇이 담기는지는
실행 전에 반드시 보여준다.

## 0. 정책 확인

`.claude/policy/operators.json` 에서 현재 작업자의 `deploy_pr` 을 읽는다.
정책이 없으면 이 명령을 쓰지 말고 CLAUDE.md §PR 기본 절차(develop 로 PR)를 따른다.

## 1. 전제 확인 (하나라도 어긋나면 멈추고 보고한다)

```bash
git rev-parse --abbrev-ref HEAD      # develop 이어야 한다
git status --porcelain               # 비어 있어야 한다 (미커밋 변경 없음)
git fetch origin
git rev-list --count origin/develop..develop   # 0 이어야 한다 (푸시 안 된 커밋 없음)
```

- 미커밋 변경이 있으면 → 커밋·푸시부터 하라고 보고하고 멈춘다.
- 로컬이 앞서 있으면 → `git push origin develop` 을 먼저 실행한다.

## 2. 담길 커밋을 사용자에게 보여준다

```bash
git log origin/main..origin/develop --oneline
git diff origin/main...origin/develop --stat | tail -20
```

커밋이 0건이면 "이미 main 과 동일합니다"라고 보고하고 **PR 을 만들지 않는다**.

## 3. PR 생성

`deploy_pr` 의 base·head·assignees 를 그대로 쓴다. 담당자를 임의로 바꾸거나 추가하지 않으며,
**자기 자신은 절대 지정하지 않는다**.

```bash
gh pr create --base main --head develop \
  --assignee <deploy_pr.assignees> \
  --title "<변경 목적이 드러나는 한글 제목>" \
  --body "$(cat <<'EOF'
## 변경 내용
- (develop 에 쌓인 커밋을 주제별로 묶어 한글로)

## 검증
- (실행한 검증 스크립트와 결과. 안 돌렸으면 안 돌렸다고 쓴다)

## 영향 범위
- (건드린 탭·배치·테이블. prod 자동배포가 걸리는 변경인지 명시)
EOF
)"
```

- `--base main` 은 **prod 자동배포**를 트리거한다(`.github/workflows/deploy-nas.yml`).
  본문 "영향 범위"에 그 사실이 드러나야 한다.
- 제목·본문은 한글로 상세히 쓴다(CLAUDE.md §커밋 메시지 규칙 준용).
- DB 마이그레이션이 포함되면 본문 맨 위에 **"⚠️ DDL 선적용 필요"** 와 실행할 SQL 을 적는다.

## 4. 보고

생성된 PR URL, base, 담당자, 담긴 커밋 수를 한 줄로 보고한다.
병합은 담당자가 한다 — **`gh pr merge` 를 실행하지 않는다.**
이 금지는 `pr-merge-guard.sh` 가 강제한다(문서만으로는 지켜지지 않아 훅을 붙였다).
