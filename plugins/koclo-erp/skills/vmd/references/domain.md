# VMD 행거 대시보드 — 도메인 규칙

## VMD 정의 (이 ERP 한정)

업계 통상 VMD(Visual Merchandising)는 매장 연출 전반을 뜻하나, **이 ERP에서는 "매장별 행거 적정 진열 수량 기획"** 이라는 좁은 의미로 쓴다.
핵심 질문: **"각 매장에 지금 옷이 얼마나 걸려 있어야 적정한가(목표)"** vs **"실제 현재고는 얼마인가"** → 부족/과잉 판단.

## 용어

| 용어 | 의미 |
|---|---|
| 행거(hanger) | 매장 옷걸이대. 사이즈(1200/1000/900/600mm)별 **상의대(u)** / **하의대(l)** 대수로 구성 |
| 1대당 용량(per_hanger) | 행거 한 대에 걸리는 벌 수. 성별×사이즈별 상수(여/남 다름) |
| 시즌배율(mult_f/mult_m) | 11구간 시즌 인덱스별 곱셈 배율. 여(`mult_f`)/남(`mult_m`) 분리 |
| 겨울기준(wb) | Σ(상의대×상의용량 + 하의대×하의용량). 시즌 인덱스 0의 환산 벌수 |
| 적정수량(sq) | `Σ(상의대×용량×배율 + 하의대×용량×(배율 or 1))`. 그 매장·그 시즌 목표 벌수 |
| 재고 계수(inventory_const) | 매장별 절대 차감값. 현재고에서 `max(0, 현재고−계수)`. 성별 분리 시 현재고 비율로 분배 |
| VMD명 | 성별 분리 단위(13개). 실제 매장(8개)을 성별로 쪼갠 이름(예: `서코여`/`서코남`) |

**VMD명 ↔ 실제매장 매핑**(`VMD_STORE_MAP`, 코드 상수 정본): 여성전용 매장 `02·04·05`(삼코·성코·마코)는 성별 무관 전체 합산. 그 외는 `M)%` 공급사명으로 남/여 버킷 분리.

## 5개 서브탭 역할·관계

| # | 서브탭 | 역할 | 쓰기 |
|---|---|---|---|
| 0 | 오버뷰 | 매장별 현재고 vs 적정수량(달성률·상태), 남/여 분리, 계수 차감, 날짜 선택 | 계수 저장 |
| 1 | 기온 & 시즌 | 월별 기온·배율·앵커·계절믹스 시각화(시즌배율 근거) | 기온 로그 |
| 2 | 월별 수량 | 12개월(최신 연도 각 달 최신 스냅샷) 매장별 현재고 | 읽기 |
| 3 | 행거 조정 | 행거 구성 편집(임시) → 시즌별 필요수량 실시간 재계산 | 행거 저장 |
| 4 | 검증 & 조정 | 600/900 고정현황·시즌효율·기온보간 vs 고정매핑 괴리 | 읽기 |

## 업무 규칙 (밴딩·임계 — 임의 단순화 금지)

- **상태 밴딩**: 달성률 90%↑ `충분` · 75%↑ `보통` · 그 외 `부족`.
- **600/900mm 하의 배율 미적용**: 하의는 `lowerMultApplies`(DB `hanger_sizes.lower_mult_applies`, 폴백 `size_mm>=1000`)인 사이즈만 시즌배율 적용. 600/900 하의는 시즌 변동 없는 고정 구간.
- **여성전용 매장 02·04·05**: 성별 무관 전체 합산(`FEMALE_ONLY_SIDS`).
- **남성 판정**: `is_male = COALESCE(공급사명,'') LIKE 'M)%'`. NULL 공급사는 여성 버킷.
- **현재고 표시 필터**(전체매장 일괄, 오버뷰 UI 조절): 상품명 `부가세` 항상 제외 · 잡화(style `AC-`) 제외 토글(기본 제외) · 매입가 `> 2000`(기본). 잡화 전용 테이블은 정반대로 `AC-`만 집계(필터·계수·폴백 없음).
- **현재고 0은 유효값** — `or` 폴백 금지(kernel §2-1). 단 매칭 0인 메인 현재고는 `DEFAULT_STOCK` 폴백 사용(데이터 공백 보정), 잡화·월별은 폴백 없이 실제 0.

## 공유 의존 (한 곳 변경 → 교차 영향)

- **5탭 전부 `GET /api/vmd/config` 단일 소스**. config 키 추가/변경은 소비 서브탭 전부 회귀.
- **`vmdCompute.js` 계산식 공유**: `wb`/`sq`(오버뷰·행거), `mq`(오버뷰 헤더·검증), `iqm`(검증), `lowerMultApplies`(행거·검증).
- **`inventory_snapshot`** 현재고 SQL·필터는 오버뷰·월별수량 공유.

구조·파일·API·DB 상세는 [[vmd-architecture]] 참조. 작업 라우팅은 `vmd` 스킬, 공통 규칙은 [[에이전트 공통 KERNEL]].

## 경계 — md-agent(기획)와 구분

`md-agent` description에 "VMD행거"가 있으나 **역할이 다르다**: md-agent는 VMD를 *입력 축*으로 쓰는 주문추천·포트폴리오 결정, vmd-\*-agent는 VMD **탭 자체**의 개발/수정. "탭 수정/기능추가/조회 화면" → vmd, "무엇을 넣을지/주문추천" → md-agent.
