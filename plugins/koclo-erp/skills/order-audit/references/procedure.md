# order-audit — 검수 절차

> 본체 `SKILL.md` 에서 분리. 검수를 진행할 때에 읽는다.

## 검수 절차

1. `scan` 으로 전체 매장 이상치 훑기 (수량0 비율·CAP·공백·중복·강화모순).
2. 의심 품목은 `explain` 으로 산식 역추적 → **"산식대로(정책)" vs "입력 데이터 오류" vs "강화 컷오프 효과"** 분류.
3. 다른 산출물이 있으면 `compare` 로 `gc`·수량 차이 원인 분리.
4. 입력 데이터(현재고·2주판매) 자체 의심 시 → DB 대조 필요. `KOCLO_ERP_DB` 는 NAS(`koclo_erp-app`),
   조회하려면 `/nas on` 필요(읽기 전용 쿼리). 결과는 추정 현재고와 대조.
5. 결론: 코드 결함 / 정책(안전재고·컷오프) / 입력 데이터 오류 중 무엇인지 한 줄로 보고.
