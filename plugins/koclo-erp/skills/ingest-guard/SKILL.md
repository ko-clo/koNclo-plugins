# 인입 포맷 방어로직(format guard) 표준

**목적**: 외부에서 받은 파일(CSV/XLSX)을 DB로 인입하기 전에 **양식 구조를 빠르게 검증**해,
잘못된 양식이 그대로 인입돼 **잘못된 데이터가 저장되는 사고를 차단**한다.
(데이터타입·셀 단위 정합은 차단 대상이 아니다 — §2 참고.)

**정본 구현(레퍼런스)**: `backend/scripts/ingest_format_validator.py` + `ingest_incremental.py` 의 가드 연결.
새 인입 경로에 적용할 때 이 구조를 **그대로 복제**한다.

---

## 1. 막으려는 실패 모드 (왜 필요한가)

파서가 상품/키 필드를 **고정 컬럼 인덱스**로 읽고 부분 정보(매장명 등)만 이름으로 찾으면,
컬럼이 하나 삽입/삭제/재정렬돼 인덱스가 밀려도 **예외가 발생하지 않고** 엉뚱한 컬럼을 읽어
저장한다. 또는 **전혀 다른 양식**(집계/외래 파일)이 같은 이름으로 들어와 가비지가 적재된다.

실제 사고 ①(가비지 적재): `증분사입흐름_YYYYMMDD_오늘.csv` 슬롯에 18컬럼 '집계일자별' 양식이
들어왔는데 `is_wide` 휴리스틱(컬럼에 매장명 존재→wide)이 상품 파서로 오라우팅 → 가비지 상품·수량을
purchase_daily 에 적재 → 잘못된 주문장 생성.

실제 사고 ②(과잉 차단, 2026-08-19): 원천이 증분사입/매출흐름 상품 블록에 '구분1/2/3' 3컬럼을
추가 → 폭 등호검사와 고정위치 앵커가 전부 어긋나 **정상 파일의 인입이 통째로 막힘**.
방어로직은 **잘못된 데이터를 막되 정상 데이터를 막으면 안 된다** — 두 사고가 같은 무게다.

## 2. 방어 패턴 4요소 (반드시 모두 갖춘다)

검증기는 **'양식 구조'만 판정**한다. 구조가 어긋나면 파일 전체를 차단한다.

1. **라벨 기반 컬럼 해석** — 필수 필드를 **고정 위치가 아니라 라벨로 찾는다**(라벨 행 1행만 읽음).
   라벨이 있으면 그 위치를 파서에 그대로 넘기고, 라벨 자체가 없으면 FAIL.
   컬럼 밀림은 '차단'이 아니라 '해석'으로 흡수되고, 파서가 안 쓰는 컬럼은 건너뛴다.
   (원천은 컬럼을 **추가**한다 — 2026-08-19 증분사입흐름에 '구분1/2/3' 3컬럼 추가. 추가돼도
   기존 컬럼은 사라지지 않으므로 라벨로 찾으면 정상 인입된다. §4 '추가 컬럼' 규칙 참조.)
2. **그룹/반복 구조 검사** — 반복 블록(매장 4열=사입/판매/재고/휴면 등)의 라벨 순서와 **블록 개수**
   확인. 블록 개수는 폭(ncols) 등호검사를 대체한다 — 상품 컬럼이 추가돼 전체 폭이 늘어도
   블록 수는 테넌트 매장 수와 같아야 하므로, 다른 테넌트 파일·블록 잘림을 그대로 잡는다.
3. **인입 전 게이트(raise)** — 검증을 **모든 DB 쓰기(commit/execute) 이전**에 호출하고,
   실패 시 `FormatValidationError` 를 raise 해 그 파일의 인입을 통째로 막는다(부분 저장 금지).
4. **호출부 처리 + 도구** — 배치 인입은 불량 파일을 **건너뛰고 '처리완료' 표시하지 않음**(교정 후
   자동 재시도). 단일 실행은 종료코드 1. **`--check` 모드**(인입 없이 구조만 출력)와
   **비상 우회 env**(`*_SKIP_FORMAT_CHECK=1`)를 제공한다.

> **데이터타입(셀 단위 숫자 여부)은 검증에서 제외한다.** 데이터 문제는 행/셀 단위라 파일 전체
> 인입을 막을 사유가 아니다 — 파서가 비숫자 값을 `safe_int→0` 등으로 흘려 **해당 행만 스킵**하므로
> 가비지가 적재되지 않는다. 구조 검사(①②)가 컬럼 밀림/외래 양식을 이미 잡는다. 데이터 정합은
> 인입 후 별도 점검(리포트/대조)의 영역이지, 인입 차단의 영역이 아니다.

## 3. 새 인입 경로에 적용하는 절차 (체크리스트)

대상 파서(예: `ingest_xxx.py`)에 방어로직을 붙일 때:

1. **파서가 읽는 필드를 전부 적는다.** 무엇을 읽는지(키/이름/가격/수량/날짜)와 그 **라벨**,
   반복 그룹의 폭과 라벨 순서. → 이게 필드 정의의 근거다. 위치(인덱스)는 라벨 행이 없는
   예외 파일용 폴백으로만 적어 둔다(`WIDE_PRODUCT_FIELDS` 의 두 번째 값).
2. **정본 양식의 ground-truth 를 실제 파일로 확보한다.** 실제 파일 1개를 열어 헤더/서브헤더/데이터
   첫 행을 찍어 라벨 위치를 확정한다(추측 금지). 빈 파일·소량 파일 변종도 확인.
3. **검증기 함수를 만든다** — `ingest_format_validator.py` 의 `validate_csv_wide` 를 본떠
   `(ok, problems, profile)` 를 반환. 필드 라벨 dict + 그룹 라벨/개수 **구조만**(데이터타입 검사는 넣지 않음).
   라벨 행 위치는 '헤더(빈 파일)' / '서브헤더(데이터 파일)' 양쪽을 모두 판별(`label_row_wide` 패턴).
   컬럼 해석은 **검증기와 파서가 같은 정본 함수**(`resolve_wide_product_cols`)를 호출한다 —
   각자 위치를 판단하면 둘이 갈려 '검증은 통과, 인입은 엉뚱한 컬럼'이 된다.
4. **가드를 연결한다** — 파서 진입부(데이터 로드 직후·행 루프/DB쓰기 이전)에서
   `_guard_format(validate_fn, ...)` 호출. 실패 시 raise.
5. **호출부를 처리한다** — 배치 루프는 `except FormatValidationError` 로 스킵+미마킹+`[FORMAT][SKIP]`
   로깅. 단일 실행은 메시지+exit 1. `--check` 서브커맨드 추가.
6. **테스트를 추가한다** — 정상 + 불량(컬럼삽입 시프트/컬럼수 오류/외래양식/빈파일) +
   **성능(데이터행 미순회)**. `test_ingest_format_validator.py` 패턴(pytest 불요, 독립 실행).
7. **실데이터 전수 점검** — 운영 폴더의 동종 파일 전부에 `--check` 를 돌려 **false-positive 0** 확인.
   (macOS 한글 파일명은 NFD → `unicodedata.normalize('NFC', name)` 후 매칭.)

## 4. 핵심 규칙 (어기면 방어로직이 무의미)

- **성능**: 전체 행을 순회하지 않는다. **라벨 행(헤더/서브헤더) 1행 + df.columns 만** 읽고
  데이터행은 접근하지 않는다. 검증기는 호출부가 **이미 로드한** DataFrame/Worksheet 를 재사용(추가 파일 I/O 0).
- **게이트는 DB 쓰기보다 먼저**. commit 이후/중간 검증은 부분 저장을 못 막는다.
- **구조만 차단, 데이터는 차단 안 함**: 컬럼 밀림·외래 양식 = 파일 전체 차단(①②). 셀 단위 데이터
  문제(비숫자 등)는 **차단 사유가 아니다** — 파서가 행 단위로 흘리고, 정합은 인입 후 별도 점검.
- **추가 컬럼은 차단 사유가 아니다**: 원천은 컬럼을 **추가**하지, 기존 컬럼을 지우지 않는다.
  필수 필드 라벨이 다 있으면 PASS 하고 모르는 컬럼은 건너뛴다. 폭(ncols) 등호검사로 막으면
  원천이 컬럼 하나 붙일 때마다 **인입 전체가 멈춘다**(2026-08-19 '구분1/2/3' 실사고).
  차단은 '라벨 소실'·'반복 블록 개수 불일치'·'블록 내부 라벨 순서 깨짐'에만 건다.
- **빈 파일 판정은 행으로**: 데이터행 0 = 인입할 게 없음 → 구조만 맞으면 PASS(오탐 금지).
  단 '빈 파일이냐'를 **파일 크기(바이트)로 재지 않는다** — 헤더 길이가 컬럼 수에 따라 변해
  컬럼이 늘면 빈 파일을 '데이터 있음'으로 오판한다. 앞 몇 줄만 읽어 헤더 아닌 행을 직접 센다.
- **외래/다른 양식 차단**: 키 라벨 행이 없으면 product 양식 아님 → 단일 사유로 FAIL.
- **멱등 전제 유지**: 검증은 인입의 UPSERT 멱등성을 바꾸지 않는다.
- **비상 우회 보존**: 운영 급할 때 `*_SKIP_FORMAT_CHECK=1` 로 게이트만 끄고 인입 가능.

## 5. 검증·실행

```bash
# 단일 파일 포맷만 점검(인입 안 함, DB 미접근)
python3 ingest_incremental.py --check --file /path/증분사입흐름_YYYYMMDD_오늘.csv
# 미처리 신규 파일 전부 점검
python3 ingest_incremental.py --check
# 단위 테스트(독립 실행)
python3 backend/scripts/test_ingest_format_validator.py
```

검증기 import 에 DB DSN 환경변수가 필요하면 더미로 채운다(`--check`/테스트는 DB 미접근):
`export KOCLO_ERP_DB_DSN="host=localhost port=5432 dbname=x user=x password=x"`.

## 6. 함정 (반복 실수)

- **is_wide 류 오라우팅**: '매장명 존재→wide' 같은 약한 휴리스틱은 18컬럼 집계 파일도 wide 로 보낸다.
  검증기의 '키 라벨 행 부재' 검사가 이를 잡아야 한다.
- **처리이력 오염**: 처리완료 표시 후 같은 이름 파일이 더 큰 실데이터로 교체되면 재인입이 skip 된다.
  포맷이 의심되면 `--check`/`--file` 로 직접 재검증한다.
- **NFD 파일명**: macOS 는 한글 파일명을 NFD 로 저장 → `glob`/정규식(NFC) 매칭 실패. 항상 NFC 정규화.
- **파일명 정규식 범위**: 인입 대상은 파일명으로 식별(예: `증분(사입|매출)흐름_…`). 그 외 이름은
  애초에 인입 대상이 아니다 — 검증기는 '인입되는' 파일만 막으면 된다.
- **같은 파일을 읽는 다른 소비자**: 인입 파서만 고쳐도 끝이 아니다. 증분사입흐름은
  `backorder_merge.py`(미송 — `/order-manual`·`backorder_db --date` 경로)가 **자기 고정 컬럼으로
  따로 읽는다**. 컬럼이 추가되면 그쪽이 조용히 스킵/오독한다. 새 양식이 오면
  `grep -rn '<파일 접두어>' --include='*.py'` 로 소비자를 전부 세고 같은 규칙(라벨/이름 해석)을 적용한다.
