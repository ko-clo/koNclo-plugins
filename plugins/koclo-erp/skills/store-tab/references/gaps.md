## 8. 알려진 갭 — 매장 스코프 (반드시 인지하고 작업할 것)

`users` 테이블에 **매장 바인딩이 없다**(`role` 만 존재: admin/manager/manager-jp/viewer).
따라서 **서버측에서 "이 계정은 자기 매장만" 을 강제할 수 없다.**

- 현재 방식: `store_user_context.py` 가 **login_id·email·name 별칭**으로 매장 계정을 식별해
  `/api/auth/me` 에 `store` 컨텍스트와 `allowed_tabs=['store-dashboard']` 를 실어준다.
  프론트는 그 코드로 매장 목록을 1개로 좁힌다. **별칭 매칭이라 정본이 아니다** —
  `users.store_code` 가 생기기 전까지는 임시 방편이고, API 응답 자체는 여전히 전 매장을 담는다.
- 관리자 계정은 화면 상단 **미리보기 매장 선택 UI** 로 매장 화면을 확인한다.
- 이 갭이 §1 E3·E4 를 **더 중요하게** 만든다 — 타 매장 지급율·매출 등 민감 지표는
  권한이 아니라 **화면 구성으로 차단**한다(애초에 매장탭에 담지 않는다).
- 후속 과제(이 스킬 범위 밖): `users.store_code` 추가 + `store` 역할 신설 + API 서버측 매장 필터.
  착수하면 이 절을 갱신한다.
