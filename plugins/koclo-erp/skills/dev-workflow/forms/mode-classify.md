# dev-workflow — 모드 분류 배너 (§2)

> 채워서 그대로 출력하는 양식. 첫 응답에서 쓴다.

## 2. 모드 분류 (첫 응답에서 반드시)

아래를 **그대로** 출력한다.

````markdown
---

### ① 모드 분류 — <기능추가 | 기능수정 | 버그해결>
`【① 분류】 ▸ ② 조사 ▸ ③ 설계 ▸ ④ 승인 ▸ ⑤ 구현 ▸ ⑥ 검증 ▸ ⑦ 완료`

> 요청의 "<인용>" 은 <근거> 이므로 **<모드>** 로 분류했습니다.
````

- 모드가 명백하면 **묻지 않고** 바로 ②③ 조사·설계로 이어간 뒤 §3 ④ 게이트에서 함께 승인받는다(왕복 2회 → 1회).
- 모드가 **모호하면 여기서 멈추고** AskUserQuestion 으로 확인한다(텍스트 질문 금지, kernel §2).
  이때도 ① 배너는 먼저 출력하고, 꼬리에 `판단 보류` 라고 적는다.
- 분류가 어려운 경계:
  - "안 되던 걸 되게" = 버그해결 / "되던 걸 다르게" = 기능수정 / "없던 걸 새로" = 기능추가
  - 계산식 변경은 **기능수정**이다(값이 갈리므로 회귀 계획이 핵심).
  - "성능 개선"은 동작 불변이면 기능수정, 새 캐시·테이블 신설이면 기능추가.
