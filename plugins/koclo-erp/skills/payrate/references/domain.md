# 지급율 관리 탭 — 도메인 규칙

## 지급율 정의 (이 탭 한정)

**지급율 = 지급금액 ÷ 매출금액 × 100** (매출 대비). 목표 `TARGET_PAYRATE = 42%`.
- **지급(분자)** = `trade_history.payment_amount` 합(사입처별).
- **매출(분모)** = `Σ sales_daily.quantity × regular_price`(regular_price>0, products→pm_suppliers JOIN).
- **분자·분모는 항상 동일 기간**으로 집계한다(다른 기간으로 좁혀 분모 0 → '지급율 0%' 사건 근본원인).
- 예외: '지급관리' 서브탭의 **이동평균**은 *사입대비*(pay/buy).

## 용어

| 용어 | 의미 |
|---|---|
| 8매장 | 본사(01)·물류(11) 제외한 실매장 8개(`STORES`) |
| 성별 지급율 | `pr_f`(여)/`pr_m`(남). 공급사명 `M)%` = 남성(`_is_male`) |
| 역마진 | 사입처 지급율 > 100% & 매출 > 0 |
| 무매출 | 매출 0 & 지급 > 0 |
| 고액외상 | 사입처 외상잔액 `credit_amount` > 50만원 |
| 물류거점 5매장 | 삼산·성남·코아울산·코아서울·홍대(`LOGISTICS_STORES`) — 본사/홍대 허브 경유 |
| 직거래 3매장 | 서면·마산·창원 — 사입처와 직접 거래 |
| 본사 / M)본사 | 허브 경유 사입처 지급(이고=즉시지급, 반품=마이너스지급) |

## 3개 서브탭 역할·관계 (단일 응답 공유)

3개 서브탭은 **단일 API `GET /api/payrate/overview` 응답 1개**(`meta`/`grand`/`stores[]`/`weekly_trend`)를 공유하며 `PayrateOverviewView.js` 안에서 `activeTab` v-show로 전환된다. 본사물류·지급관리는 같은 응답을 **프론트에서 재구성**(API 추가 없음).

| 서브탭 | 역할 |
|---|---|
| 오버뷰 | KPI·성별 지급율·매장별 표·주간추이·역마진/무매출 경보 |
| 지급관리 | 목표 대비 실적·주별 지급 추이·이동평균(사입대비)·고액외상 |
| 본사물류 | 물류거점 vs 직거래 6지표·흐름도·본사/M)본사 지급·비교 |

## 밴딩 임계 (정본 `rebuild_payrate_db.py` — 임의 단순화 금지)

- **매장·성별**(`prColor`): >48 빨강 · >45 노랑 · <40 파랑(미달) · 40~45 초록.
- **합계**(`prColorGrand`): ≤45 초록 · ≤48 노랑 · >48 빨강.
- **사입처**(`prColorSup`, 사입대비): >100 빨강 · >80 노랑 · 그외 초록.
- **목표 판정**: 목표×0.9 이하 미달 · ×1.1 이하 적정 · ×1.3 이하 주의 · 초과 초과.

## 공유 의존
- 3 서브탭 전부 `/api/payrate/overview` 단일 소스. 응답 스키마 변경은 전부 회귀.
- `PayrateOverviewView.js` 단일 파일(공통 toolbar·날짜·포맷터). `PayrateTrendChart.js`는 오버뷰·지급관리 공유.

구조·파일·API·DB는 [[지급율 관리 탭 아키텍처]] 참조. 라우팅은 `payrate` 스킬, 공통 규칙은 [[에이전트 공통 KERNEL]].

## 경계 — '지급' 3중 충돌 (반드시 구분)
- **payrate(지급율, `/payrate`, `PayrateOverviewView`)** ← 이 시스템. *이 탭 안의 '지급관리' 서브탭(management)도 포함*.
- **지급관리(`/payment`, `PayrateView`)** ← 별개 최상위 탭, `auto-payment-agent` 담당(영수증OCR·자동지급). **건드리지 않음**.
- **md-agent** ← 지급율을 *기획 입력 축*으로 사용(`md-agent-payrate-knowledge.md`). 탭 개발 아님.
