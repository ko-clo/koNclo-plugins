# 카카오 채널 — 불변 규칙

설계안에 해당 항목 번호를 적는다.

| # | 규칙 | 어기면 |
|---|---|---|
| K1 | LLM 은 `run_via_hermes(domain="kakao")` 로만 부른다. ERP 가 LLM·임베딩 API 를 직접 부르지 않는다 | 종량 과금(R1 위반). 벡터 경로는 이 이유로 폐기(09-28) |
| K2 | 요청당 **유료 외부 호출**을 설계안 맨 앞에 적는다. 소규모면 DB 내장·규칙부터 | 구현 후 전 과정 폐기 |
| K3 | 격리는 `HERMES_SEND_MODE=1` + Hermes `koclo-erp-kakao` + `memoryless_modes: [kakao]` 셋이 다 있어야 성립 | 사입처 발화에 전 도메인 쓰기 도구·운영자 기억 노출 |
| K4 | kakao MCP 에 새 도구 = `registries/kakao.py` + `catalog.py` `EXPOSED` 2곳. 원가·지급액·수량·타 사입처 정보는 노출 금지. 쓰기 도구 금지 | 사입처에게 내부 정보 유출 |
| K5 | 사입처에게 나가는 답은 안전 필터(`is_sendable_codex_reply`)를 통과해야 한다. 금액·날짜·입금/결제/잔액·`NEED_STAFF` 는 규칙 답으로 대체 | 잘못된 약속이 본사 명의로 발송 |
| K6 | 스킬 응답 5초 제한. 느린 일은 `useCallback` + 백그라운드. callbackUrl 은 1회용·최대 5분, `*.kakao.com` 만 허용 | 무응답·SSRF |
| K7 | 봇 채널은 **1:1 채팅 OFF** 여야 봇이 받는다. 운영채널에 봇을 붙이면 채팅함 수신이 사라진다 | 봇 무응답 / 담당자 대화 소실 |
| K8 | 로그에 발화 원문·토큰을 남기지 않는다(길이만) | 개인정보 노출 |
| K9 | 새 env 는 compose `environment` 두 파일(`docker-compose.yml`·`.dev.yml`)에 추가 + 컨테이너 재생성. restart 로는 안 들어간다 | 운영에서 기본값으로 동작 |
| K10 | 컨테이너 안에서 ERP API 를 부를 땐 `http://127.0.0.1:9000`. 공개 URL 은 Cloudflare 403(1010) | 인입 실패 |
| K11 | 인입은 멱등이어야 한다(`since` 워터마크·UNIQUE). 재실행 0건 삽입을 검증 | 대화 중복 |
| K12 | 사입처 매핑은 `kakao_room_suppliers` 확정값만 쓴다. 방 이름 휴리스틱으로 단정하지 않는다 | 다른 사입처 대화를 근거로 답장 |
| K13 | 사용자 목표(09-27): 사람이 쓰는 비즈니스 채팅 통로로 자동발송이 핵심. 사입처에게 버튼 누르게 하는 흐름 금지 | 목표 이탈 |
