# post-verification — 입력·출력·예외·로깅 체크 (§2 ~ §5)

> 본체 `SKILL.md` 에서 분리. 각 체크를 수행할 때에 읽는다.

## 2. 입력 체크

반드시 실제 입력 경로 기준으로 확인한다.

- 필수값 누락, 빈 문자열, `null`, 0, 음수, 잘못된 날짜/기간 역전.
- 목록/필터/탭/토글 등 UI 입력 상태 변경.
- 중복 요청, 재실행, 기존 데이터가 있는 상태.
- 파일 인입이면 컬럼 구조, 파일명 패턴, 빈 파일, 외래 양식.
- 사용자가 보낸 값이 조용히 전체 범위나 기본값으로 폴백하지 않는지 확인한다.

## 3. 출력 체크

정상 결과와 실패 결과를 나눠 확인한다.

- 성공 응답: 필드명, 타입, 단위, 날짜/기간, 합계, 정렬, 빈 값 표현.
- 화면 출력: KPI, 테이블, 차트, 이미지/모달, sticky/scroll, 모바일/폭 좁은 상태.
- 저장/인입 결과: 건수, 날짜 범위, 중복 흡수, 기존 데이터 보존.
- 오류 출력: 사용자 메시지는 안전하고, 내부 진단 정보는 로그에 남는다.
- 기존 oracle이 있으면 기존 HTML/리포트/정본 쿼리와 수치를 대조한다.

## 4. 예외 처리 체크

- 외부 API, DB, 파일, 네트워크, Docker/NAS 호출 실패가 명시적으로 처리되는지 확인한다.
- 처리 가능한 예외만 잡고, 처리할 수 없는 예외는 맥락을 보존해 상위로 전달한다.
- 예외를 삼키거나 빈 결과로 위장하지 않는다.
- 실패 중간에 부분 저장, 부분 삭제, 처리완료 마킹이 남지 않는지 확인한다.
- UI는 실패 시 무한 로딩이나 빈 화면으로 멈추지 않는다.

## 5. 로깅 체크

- 실패 로그는 원인 추적에 필요한 식별자, 날짜, 단계, 파일명, 건수를 포함한다.
- 성공 로그는 운영 판단에 필요한 상태 변화만 남긴다.
- 비밀번호, 토큰, DSN, 개인정보, 원본 운영 데이터 덤프를 로그나 최종 응답에 노출하지 않는다.
- 같은 의미의 로그를 여러 곳에 중복 추가하지 않는다.
